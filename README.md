# dsh-soundcheck

给 DeepSeek Harness 加本地音乐分析能力 —— 让文本模型能回答关于一首歌的问题。

**全程本地**：音频不出本机、不联网、不上传 · **Windows 专用** · CPU 可跑，不需要 GPU

---

## 这是什么

一个 DSH 插件。装上之后直接在对话里问「这首歌多快」「有没有人唱」「哪段最炸」，
模型会调它给出的四个工具，拿回实测数据再回答。

它不猜、不编：测得到的给数字，测不到的明说测不到。

## 干什么用

| 能回答 | 怎么答 |
|---|---|
| 多长、多快 | 时长；BPM 两层（如 78 / 156），不替你挑哪层是「真速」 |
| 什么调 | Krumhansl 模板 + Top3 候选 + 歧义分类 |
| 多响、有没有削波 | 真峰值、整体 RMS、贴顶采样数、整合响度 LUFS |
| 能量怎么走 | 16 秒块 RMS 走势、最满在哪、最大反差、怎么收尾 |
| 有没有人唱 | 分轨占比 + 人声段（哪几段在唱）+ 相对电平 |
| 各轨占多少 | 4 轨（人声 / 鼓 / 贝斯 / 其他）或 6 轨（再加吉他 / 钢琴） |
| 歌词 | 机器听写的候选段 —— 是候选，不是精确歌词 |
| 音高 | 音域、趋势、有声占比、最长连续秒数 |
| 某一段怎么回事 | 指定 `[start, end]` 单独分析 |

**测不到什么**（工具会直接说，不会硬编）：

- **具体乐器名** —— 中文民乐基本没有（实测会把唢呐报进没有唢呐的曲子）
- **情绪、氛围、场景、语义联想**
- **音符级旋律** —— 音高只有轮廓

## 安装

```sh
dsh plugin add ALittleLov/dsh-soundcheck
```

第一次分析之前先装引擎：

```sh
/audio-install
```

它建 venv、装 librosa + onnxruntime、下载模型（约 570 MB）。

分轨与歌词听写是**可选组件**，不装也能用其余全部能力；缺组件时工具会明说缺什么。

## 都有什么

### 四个工具

| 工具 | 作用 | 参数 |
|---|---|---|
| `audio_analyze` | 分析整首音频 | `path` `format` `brief` `detail` `blocks` `stems` `preview` `asr` `async` |
| `audio_section` | 只分析一段 | `path` `start` `end` `format` `brief` `detail` `blocks` |
| `audio_bands` | 分频段诊断 | `path` `start` `end` |
| `audio_provision` | 装引擎 | `stems` `asr` |

常用参数：

| 参数 | 作用 |
|---|---|
| `format: json` | 结构化输出（给程序用） |
| `brief: true` | 配合 json，只留结论级字段，约 130 token |
| `detail: true` | 输出完整测量明细 |
| `stems: 4s \| 6s` | 分轨（可选组件，首次 60–90 秒，之后读缓存） |
| `asr: tiny \| base \| small` | 歌词听写（可选组件，默认关闭） |
| `preview: true` | 快速预览，6–40 秒出结果，不跑分轨 / ASR |
| `async: true` | 后台任务，立即返回 job id（分轨 / 听写建议开） |

`audio_bands` 是分频段诊断：把频谱切 5 段（30–250 / 250–800 / 800–2500 / 2500–6000 / 6000–12000 Hz），
给每段的能量占比、打击密度、间隔规律性 `cv`。用来判断「这是音乐还是野外录音」、
验证某一层打击到底在不在。内部诊断用，不进主报告。

### 两个命令

| 命令 | 作用 |
|---|---|
| `/audio-status` | 看引擎状态（Python 环境 / 脚本 / 模型 / 安装标记） |
| `/audio-install` | 一键装引擎，返回装了什么、走了哪个镜像 |

## 怎么用

直接用自然语言问：

```
帮我看看 D:\Music\track.flac 这首歌什么情况
这首 2:40 那一段是怎么回事
这首有没有人唱？哪几段在唱？
```

要细节就加一句：

```
用 detail 看完整测量明细
只看 1:30 到 2:10，给我 json
```

装不上或想手动跑，命令行也能用：

```bash
cd <插件目录>/engine
export PYTHONUTF8=1          # Windows 上必须,否则中文输出会崩
python analyze.py "<音频路径>"
python analyze.py "<音频路径>" --detail
python analyze.py "<音频路径>" --json --brief
python analyze.py "<音频路径>" --start 1:30 --end 2:10
python analyze.py "<音频路径>" --stems 6s
python analyze.py "<音频路径>" --asr base
python analyze.py "<音频路径>" --pitch
python analyze.py "<音频路径>" --preview
```

## 输出长什么样

默认一段判断，数字只在依据里：

```
[判断]  一段人能直接读的结论:时长 / 速度层级 / 调性 / 母带 / 结构重心 / 最大反差 / 收尾
[依据]  判断背后的数字:峰值、RMS、起音、调性、拍速
[可信]  beat / 调性 / 根音 的适用性分数(0-1)
[听不到] 这类分析听不出来的东西
```

装了可选组件才会出现的段：

```
[分轨]  各轨能量占比 + 人声判定
[听写]  机器听写的候选段
[标签]  模型预测标签,仅作辅助参考
[音高]  音域 / 趋势 / 有声占比 / 最长连续秒数
```

## 已知限制

- **片段 BPM 不等于全曲 BPM**：短片段会锁到别的拍层级，输出里会警告
- **和弦只到根音级**：七度、挂四、转位在混音里分不出来
- **歌词是候选**：音对字错是常态；非中文人声只给音译，不翻词义
- **中文乐器识别不可靠**：所以判断里不写配器行
- **音高是轮廓不是音符**：给不了调式、旋律走向的名字
